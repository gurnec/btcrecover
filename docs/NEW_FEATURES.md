# Proposed New Features for Password Generation

This document outlines several proposed new features to expand the password generation capabilities of `btcrecover`. These features are designed to broaden the project's utility by supporting a wider range of password recovery scenarios.

## 1. Character Set Expansion

**Problem:** While `btcrecover` supports custom character sets through the `%[...]` wildcard syntax, it can be cumbersome for users to define large or complex character sets on the command line.

**Proposed Solution:** Introduce a new command-line option, `--charset`, that provides a more user-friendly way to define and use character sets.

### User Interface

The `--charset` option would accept one of two types of arguments:

1.  **Named Character Sets:** Pre-defined, commonly used character sets.
    *   `--charset all-printable-ascii`
    *   `--charset alphanumeric`
    *   `--charset lowercase-alpha`
    *   `--charset uppercase-alpha`
    *   `--charset digits`
    *   `--charset symbols`

2.  **Character Set File:** A path to a file containing a custom character set.
    *   `--charset file:my_custom_chars.txt`

These character sets could then be used in wildcards, perhaps with a new, simpler syntax, or by assigning them to a custom wildcard slot. For example, a user could define a charset and then use it in a token:

`tokens.txt`:
```
mypassword%1,4{charset1}
```

### Implementation Sketch

1.  **`parse_arguments()`:**
    *   Add the `--charset` argument to the parser.
    *   If a named set is provided, load the corresponding characters into a dictionary.
    *   If a file is provided, read the file and store its contents.
2.  **`expand_wildcards_generator()`:**
    *   Modify this generator to recognize the new charset syntax (e.g., `%{charset1}`).
    *   When this syntax is encountered, use the characters from the specified charset for expansion.

This feature would build upon the existing wildcard system, making it more powerful and easier to use.

## 2. Pattern-Based Generation

**Problem:** `btcrecover`'s token-based system is excellent for when a user remembers fragments of their password but not the order. However, many users create passwords based on predictable patterns, such as `word-year-symbol` or `name_birthday`. The current system doesn't have a straightforward way to represent and generate these patterns.

**Proposed Solution:** Introduce a new "pattern file" mode that allows users to define structured password patterns. This would be a powerful new way to generate password candidates.

### User Interface

A new command-line option, `--pattern-file`, would be used to specify a file containing password patterns. The syntax of the pattern file would be simple, with each line representing a pattern to be expanded.

`patterns.txt`:
```
{wordlist:common_words.txt}-{charset:digits:4}-{charset:symbols:1}
{wordlist:names.txt}_{charset:digits:8}
```

The syntax `{type:source:length}` would define a component of the pattern:
*   `type`: The type of component, e.g., `wordlist` or `charset`.
*   `source`: The source of the data, e.g., a file path or a named character set.
*   `length`: The number of items to select from the source (for charsets) or the exact length of the generated string (for digits).

### Implementation Sketch

1.  **`parse_arguments()`:**
    *   Add the `--pattern-file` argument.
    *   If provided, this will signal `password_generator()` to use a new base generator.

2.  **`pattern_base_password_generator()`:**
    *   This new generator function would be responsible for parsing the pattern file.
    *   For each line in the pattern file, it would parse the pattern into its components.
    *   It would then iterate through all possible combinations of the components, yielding a fully formed password for each combination. For example, for the pattern `{wordlist:common_words.txt}-{charset:digits:4}-{charset:symbols:1}`, it would:
        1.  Read a word from `common_words.txt`.
        2.  Generate a 4-digit number.
        3.  Select a symbol from the `symbols` charset.
        4.  Combine them into a single password string, e.g., `password-2023-!`.

3.  **`password_generator()`:**
    *   This main generator would be modified to accept `pattern_base_password_generator` as a base generator.
    *   The passwords generated by the pattern generator would then be passed through the existing typo-generation system, allowing users to combine pattern-based generation with typo simulation.

## 3. External Wordlist Integration

**Problem:** While users can technically use external wordlists by pasting them into a `tokens.txt` file, this is not ideal for large wordlists (like `rockyou.txt`). Loading a massive file into memory as a token list can be inefficient and may not be necessary if the words are just being used as one part of a larger password generation strategy.

**Proposed Solution:** Introduce a new command-line option, `--wordlist-tokens`, to directly integrate external wordlists as a source of tokens.

### User Interface

The `--wordlist-tokens` option would take a file path as an argument:
```
--wordlist-tokens /path/to/rockyou.txt
```

The words from this file would be treated as a list of mutually exclusive tokens, similar to a single line in a `tokens.txt` file. This would allow users to easily combine a large wordlist with other tokens or patterns.

For example, a user could have a `tokens.txt` file like this:
`tokens.txt`:
```
+ 2023
! @ # $
```
And run `btcrecover` with:
```
btcrecover.py --wallet wallet.dat --tokenlist tokens.txt --wordlist-tokens rockyou.txt
```
This would generate passwords like `password2023!`, `1234562023@`, etc., where the word part comes from `rockyou.txt`.

### Implementation Sketch

1.  **`parse_arguments()`:**
    *   Add the `--wordlist-tokens` argument.
    *   If provided, store the file path.

2.  **`parse_tokenlist()`:**
    *   If `--wordlist-tokens` is specified, this function would be modified to read the wordlist file.
    *   Instead of loading the entire file into memory, it could create a generator that yields words from the file one by one. This would be much more memory-efficient for large files.
    *   This generator would then be added to the `token_lists` structure as a new list of tokens.

This feature would make it much easier and more efficient to use large, common password lists in `btcrecover`, significantly expanding its power for dictionary-based attacks.
